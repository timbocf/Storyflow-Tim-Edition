Video Frames & Dialog

Three Frames instructions set how long the next video render runs, and a fourth — Frames by Dialog — works the length out from spoken lines. All four export as the same underlying frames setting in Draw Things; which model you have loaded decides what a given count means.

The three frame rules

The frame counts aren't free-form numbers. Each video family only accepts counts on a pattern, and the Editor's sliders snap to it:

InstructionPatternExamplesFrame rateRange
Frames — WanSteps of 4, offset 1 (4n+1)1, 5, 9, 13 …16 fpsup to 128 (≈8 sec)
Frames — LTXSteps of 8, offset 1 (8n+1)1, 9, 17, 25 …25 fpsup to ~1000
Frames — H3Steps of 17, offset 55, 22, 39, 56 …24 fpsslider 0 = 1 frame (a still)

The odd patterns are the video models' own rules, not Storyflow being awkward — the models generate in blocks, so counts in between patterns aren't valid. Each slider shows the frame count and the matching seconds as you drag.

Tim Edition fix: in the original Editor, the H3 slider's badge followed the H3 rule but the export used the Wan/LTX "+1" shortcut — a badge reading 22 exported 18. The Tim Edition exports what the badge shows. See Tim Edition Changes.

Frames by Dialog (💬)

This one answers "how long should this clip be?" from the script itself:

  1. It reads the current concat bucket and finds everything inside double quotes — your spoken lines. The original counted only straight quotes ("..."); the Tim Edition also counts curly quotes (“...”), which iPad/iPhone keyboards type by default — with the original, dialogue typed on an iPad counted as zero words and clips came out far too short.
  2. It counts the words in those lines.
  3. It converts words to time using your Words Per Second setting (the Editor clamps it to 1.2–3.2; default 2.4 — a natural speaking pace).
  4. It rounds the result up to the loaded model's frame pattern and adds your Pad Frames (default 49, snapped to an 8n+1 value) — breathing room before/after the line.

Which pattern? The Pipeline looks at the loaded model's name: if it contains "H3" it uses 24 fps / step 17 / offset 5; anything else gets 25 fps / step 8 / offset 1 (the LTX rule).

Tim Edition fix: the original table only special-cased H3, so Wan models silently got the LTX rule and dialog clips ran long. The Tim Edition's table also matches model names containing "wan" and applies the proper 16 fps / step 4 / offset 1 rule. Anything that matches neither H3 nor Wan still uses the LTX rule as the default.

The Generate checkbox

Frames by Dialog has an optional Generate box. Tick it and the instruction also renders on the spot, using the bucket as the prompt — no separate Prompt item needed, and the preflight render counter counts it as a render. Leave it unticked and it only sets the frame count, so the following Prompt (or video instruction sequence) renders with that length.

Worked example

Bucket contains: A cowboy turns to camera. "Well, I reckon this town ain't big enough for the both of us."

  • Quoted words: 13
  • At 2.4 words/sec → ≈5.4 seconds of speech
  • On an LTX-pattern model (25 fps): 5.4 sec → 136 frames → rounded up to the 8n+1 pattern → 137, plus 49 pad frames → 186 → snapped to pattern as the code rounds and pads — the point is the length comes from the line, not from a guess.
