How It Works

Storyflow splits one job between two programs that never talk to each other directly. The Editor is a recipe builder. The Pipeline is the cook. The hand-off between them is a block of text.

The journey of a job

  1. Build. In the Editor you stack instruction blocks in order — clear the canvas, set the size, build a prompt, render, save.
  2. Export. Export to Pipeline downloads a .txt file (or Export to Clipboard copies it). The export is a JSON list of small one-key objects, in the order of your list, ending with an end marker: 
    [
  {"note": "My first project"},
  {"canvasClear": true},
  {"size": {"width": 1920, "height": 1280}},
  {"concat": "a portrait of "},
  {"prompt": "@hero, smiling, studio light"},
  {"canvasSave": "myProject/result.png"},
  {"end": true}
]
  3. Paste. In Draw Things you run the StoryflowPipeline script. The first popup (Menu A) is a big text box — paste the whole export, brackets and all.
  4. Preflight. The script checks your instructions before running anything (Menu B — see below).
  5. Run. Press Start Pipeline. The script walks the list top to bottom, doing each instruction against the live Draw Things canvas, and stops at the end marker.

The three pieces of state

Almost every instruction exists to change one of three things the Pipeline carries through the run:

StateWhat it isWho changes it
configurationThe Draw Things settings the next render will use — model, steps, LoRAs, sampler, size, and so on. Starts as whatever Draw Things is currently set to. Config-type instructions overwrite individual settings in it; nothing renders until a Prompt fires. Changes stay changed in Draw Things after the run ends.Config, Size, Sweep, Frames, High-res Fix, In-paint Tools, XL Magic…
concatA text bucket, empty at the start. Text instructions pour prompt words into it. A Prompt instruction renders using everything in the bucket plus its own text — then empties the bucket for the next render. This bucket is the heart of Storyflow: most prompt features exist just to build it up in stages.Concat, Wildcard, Interrogate, Enhance, Prefix, Get Prompt, Approve…
maskA sticky mask layer. Once set, it is handed to every render (for inpainting) until it is cleared.Load Mask, Foreground/Background Mask, Body Mask, Clear Mask…
Why nothing renders: if your list has no Prompt instruction (and no Frames-by-Dialog with its Generate box ticked), the run will happily do all the preparation and finish without rendering a single image. Preparation is not rendering.

The Preflight Check (Menu B)

Before running, the Pipeline validates the pasted instructions and shows you a report. Read it like a checklist:

  • Number of renders — how many Prompt instructions (plus generating Frames-by-Dialog items) it found.
  • Models — every model named anywhere in your Config items (including LoRA files), marked 🔹 downloaded or 🔸 not available locally. A 🔸 model will fail or fall back when the run reaches it.
  • Files — every save (🔻) and load (🔺) path, relative to your device's Pictures folder. Two warnings baked into this screen: folders are not created for you (a save into a folder that doesn't exist will fail), and a save will overwrite a file with the same name.
  • Answer model — if the job uses Interrogate, Enhance, or Ask Zoom, you also pick which vision model answers: interrogate default, Qwen 3.5 4B (recommended if your device can run it), or Moondream2.

If validation fails — bad JSON, an instruction the Pipeline doesn't recognize, a wrong value type, a save path that doesn't end in .png — Menu B instead lists every problem with troubleshooting notes. In the Tim Edition the script then stops and runs nothing (the original would continue if you confirmed the warning screen — see Tim Edition Changes).

Two popups where the run waits for you

Most instructions run hands-free, but two are deliberate pauses:

  • Swap — stops so you can pick or replace the canvas image yourself.
  • Approve — stops and shows the current concat bucket in an editable box. Whatever you leave in the box is what the next Prompt renders with. It belongs right after an Interrogate or Enhance, so you can fix the model's wording before it becomes a prompt.

House rules worth knowing

  • Instructions run strictly top to bottom. Order is the whole programming language.
  • File paths in instructions are relative to the device Pictures folder. Loads accept PNG/JPG/WebP; saves must be PNG.
  • If no Config instruction ever names a model, the job runs on whatever model you already had loaded in Draw Things.
  • The Editor and Pipeline are versioned together (261101). Keep them matched — an Editor newer than the Pipeline can export instructions the Pipeline will reject at preflight.
