Wildcards, Sweeps & Loops

These are Storyflow's variety machines. A Wildcard picks prompt text from a list of cards. A Sweep does the same thing to a Draw Things setting. A Loop repeats a block of instructions so the picking actually gets used. All three are usually found together.

Don't confuse the two "wildcards": the $name wildcards in the Editor's Wildcards tab are picked once, at export time, and the exported text is fixed. The Wildcard instruction on this page is picked at runtime, inside Draw Things, every time the run reaches it. Same word, different machine.

The Editor's $ wildcards (the Wildcards tab)

Define these in the Editor's Wildcards library tab, then use them inside prompt text — Add Text, Prompt, Prefix, Negative — by typing a dollar sign and the name: $tall blonde. There is no instruction item for them; they live in your text.

PieceHow it works
NamePlain words are fine — spaces included (tall blonde). The $ is optional in the name field; typing it there too is harmless. Use the name in text as $tall blonde.
ValueOne phrase, or several options separated by | — e.g. blue sky|dawn|sunset. A single phrase with no | is a reusable snippet: it is swapped in as-is, every time.
PickingHappens once, at export: a random option is chosen and baked into the exported text (re-export to re-roll). Preview shows the first option so you can sanity-check. $sky[2] forces option 2 exactly.
Where it worksPrompt-bearing text (Add Text / Prompt / Prefix / Negative). Inside the Wildcard instruction below, use its 📚 Fill cards from Wildcards tab dropdown: picking a tab entry copies that entry's options into the node's cards (a one-time snapshot — later tab edits don't rewrite nodes you've already filled).

The six picking modes

Wildcard and Sweep share the same six modes. Each individual Wildcard/Sweep item keeps its own place in its own list — two items never share a counter (except in loop mode, below).

ModeHow it picksGood for
loopSteps through the cards in order, wrapping to the start. It advances with the loop counter, not with how many times the item is hit — so two Wildcards on loop mode stay in step with each other, and hitting the same one twice in one pass gives the same card twice. A Wildcard on loop mode outside any loop always gives card 1.Matched sets: outfit #3 with pose #3 with background #3.
onceSteps through in order with its own counter, but stops on the last card and keeps giving that one forever.Progressions that settle: a ramp that ends at a final value.
shuffleDeals the cards in random order like a deck — every card appears once before any repeats — then reshuffles.The best default for variety without repeats. The sample projects lean on it heavily.
randomA fresh random pick every hit. Repeats can happen, even back to back.Chaos, brainstorming, big lists where repeats don't matter.
menuPauses the run and lets you pick from a popup, every time it's hit.Steering a run by hand.
comboboxLike menu, but the popup also lets you type your own text instead of picking.Picking with an escape hatch.
Menu/combobox inside a loop: they ask every pass. A 50-pass loop with one menu Wildcard means 50 popups. That's a feature if you're supervising, and a trap if you're not.

Sweep specifics

A Sweep names one setting (paramName, e.g. steps or stochasticSamplingGamma) and a list of value cards. Each hit sets that one setting to the picked card; the setting stays changed until something else changes it. Card values are interpreted by content:

  • Written as JSON (a list in [...], an object in {...}) → parsed as JSON. This is how a Sweep can rotate LoRA stacks or model names.
  • A plain number → becomes a number.
  • Anything else → stays text.
No safety net: Sweep values are not checked against any range. The original doc says this plainly — you can set values outside safe limits and Draw Things will try to use them. Double-check spelling too: a mistyped paramName just sets a setting that doesn't exist, silently.

Loops

A Loop item and an End Loop item bracket a block of instructions. The block repeats Loop Count times. Start Index sets the number used for the first saved file. Rules:

  • No nesting. One loop at a time — a Loop inside a Loop doesn't work. Several loops one after another in the same project are fine.
  • The loop has its own counter, which is also what drives loop-mode Wildcards/Sweeps and the incremental file instructions below.
  • A typical loop body: build a prompt (Concat + Wildcards) → Prompt → Save Image ⓘ. Each pass produces one variation, saved automatically.

Incremental files (the ⓘ instructions)

Four instructions only make sense inside a loop. They advance in step with the loop counter:

InstructionWhat advances
Load Image ⓘEach pass loads the next image from a Pictures folder onto the canvas.
Load ⓘ MaskEach pass loads the next mask from a folder — pair with Load Image ⓘ (same sorting) to batch-process a folder of images with matching masks.
Add ⓘ MBEach pass adds the next image from a folder to the moodboard.
Save Image ⓘEach pass saves the canvas as name_001.png, name_002.png, … counting up from Start Index (three-digit numbering).

Folder sorting: files are ordered by a leading number before the first underscore if they have one (2_b.png comes before 10_a.png), otherwise alphabetically. If the loop runs more passes than there are files, the sequence cycles back to the first file.

A minimal variety loop, read aloud

Loop {count: 8, start: 1}
  Concat     "a portrait of a woman, wearing "
  Wildcard   (shuffle) cards: "a red coat" | "a denim jacket" | "a black gown"
  Concat     ", standing in "
  Wildcard   (shuffle) cards: "a forest" | "a city street" | "a desert"
  Prompt     ", golden hour light"
  Save Image ⓘ  "portraits/look"
End Loop

Eight passes, eight renders, each with a different outfit/place pairing (shuffle means no outfit repeats until all three are used), saved as look_001.png through look_008.png. Swap one Wildcard to loop mode and the pairings lock into matched rotation instead.
