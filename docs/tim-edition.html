Tim Edition Changes

This fork starts from wetcircuit's Storyflow 261101 (November 2026) and fixes bugs found by reading the code closely. Every change is marked in the source with a [Tim edition fix] comment next to the changed lines, so the differences are easy to find, review, or revert. The full log is CHANGELOG_tim.md in the repo.

Fixed

#FixWhat was wrong
1H3 frames export (Editor)The MiniMax H3 frames slider displayed values on the H3 rule (steps of 17, offset 5) but the exporter applied the Wan/LTX "+1" shortcut to all three frame types — a badge reading 22 exported 18. Export now matches the badge for all three types. Verified against all 181 slider positions, including save/load round-trips: the original mismatched on 21 positions (every H3 stop past the first); the fixed code mismatches on none.
2Preflight hard stop (Pipeline)When preflight found problems (bad JSON, unknown instructions, wrong types, bad file paths), the script showed a "🚫 Pipeline will fail" screen but kept executing if that screen was confirmed instead of cancelled — running a job it had just declared invalid. Now any collected warning stops the script with an error after that screen. Fix in the Editor, re-export, relaunch.
3Get Prompt appends (Pipeline)The instruction's own comment said "concatenate prompt," but the code replaced the whole concat bucket with Draw Things' UI prompt, silently throwing away text built up by earlier Concat/Wildcard/Interrogate items. It now appends, like the other bucket-building instructions.
4Export to Clipboard on iPad (Editor)The original was a single clipboard call with no error handling and no feedback. On iPad that API only exists in secure contexts (https — not local files or in-app previews) and fails silently when blocked, so the button appeared dead. The button now tries three routes in order — modern Clipboard API, legacy select-and-copy, and a manual-copy popup with the text pre-selected — and reports the result on the button itself. (Running the Editor from this site's https address also gives the modern route its best shot.) Side discovery: the Editor also calls a toast-notification function that is never defined anywhere in the file, so it had no working feedback mechanism at all.
5This documentation, linked from the Editor headerThe original's only in-tool help was placeholder text inside empty fields, plus a separate .txt doc most users would never find. This wiki covers the whole system.
6Frames-by-Dialog Wan rule (Pipeline)The dialog-timing model table only had an H3 entry; everything else fell through to the LTX default (25 fps, step 8), so dialog clips on Wan models ran long. A Wan entry (16 fps, step 4, offset 1) was added in the author's own pattern. Verified by harness: 13 words at 2.4 wps → 141 frames (H3), 89 (Wan), 137 (LTX).
7Mask seam mostly closed (Pipeline)File-loaded masks were invisible to the Pipeline's mask state: a stale internal mask could override a freshly loaded file mask at render time, and Mask to Canvas couldn't show file masks at all. File masks are now tracked by source — loading one supersedes the internal mask, internal masks supersede the record in turn, Mask to Canvas falls back to the file, and Clear Mask forgets both. One limit remains (below).
8Answer-model menu lookup (Pipeline)The preflight answer-model popup was located by counting menu sections by hand (3 + files + answers); a future section change would have silently read the wrong slot and used the wrong answer model. The menu's position is now captured while the menu is built. (Also removed a dead check for a nonexistent "askMask" instruction.)
9Resolver loop caps (Editor)All four shorthand resolvers (triggers, config shortcuts, pose shortcuts, Editor wildcards) expanded until the text stopped changing, with no limit — a growing cycle (A contains B twice, B contains A twice) looped forever and froze the tab. The loops now stop after 10 passes or 200k characters; the size cap matters because a growing cycle doubles the text each pass. Normal nested definitions resolve exactly as before.
10Preview totals (Editor)Wan/LTX totals used a running-subtraction formula that only came out right for a single frames item (two 81-frame Wan items "totaled" 161, with seconds off the wrong base). Totals are now plain sums, H3 has its own total line, and per-item seconds use frames ÷ fps to match the item badges.
11Duplicate item button (Editor)There was no way to copy an item — rebuilding a near-identical Prompt or Config meant retyping it. Every item now has a ⧉ button that copies it, values included, directly below itself. File-embed items even copy the picked file's contents.
12Undo (Editor)One wrong delete or drag was permanent. Add, delete, duplicate, reorder, Load and New now snapshot the project first; ↩️ Undo (or Ctrl/Cmd+Z outside text fields) steps back through up to 30 states.
13Autosave (Editor)Closing the tab lost unsaved work. The project now autosaves to the browser's local storage after every change and is restored on load when it's more than a fresh empty project.
14JSON validation in the Editor (Editor)A Config item with empty or broken JSON exported malformed output that only failed later in Draw Things. Bad JSON is now flagged in the list (red outline + ⚠), named in Preview, and both export buttons refuse until it's fixed. Form-builder JSON is checked too.
15Help on every item (Editor)Items explained themselves only through placeholder text. Each of the 55 item types now shows a one-line plain-language description under its label.
16Preview shows expansions (Editor)Preview showed raw shortcut text for Config/Pose and ignored $ wildcards. It now shows Config/Pose with # shortcuts expanded, and prompts with $ wildcards shown as their first option (the real export still rolls randomly — Preview stays deterministic).
17Clipboard copy, second hardening (Editor)Fix 4 awaited the modern Clipboard API first and fell back afterward; on iPad Safari, copy permission is tied to the tap and that wait could let it lapse, so the button still appeared dead. The synchronous select-and-copy route now runs first, inside the tap; the API route also fires in webviews that leave isSecureContext undefined; and the manual popup gained its own "Select & Copy" button (a fresh tap is a fresh copy gesture) plus an editable text box, since some iPad Safari versions won't offer the Copy callout on a readonly field.
18Curly quotes count as dialogue (Pipeline)Frames-by-Dialog found spoken lines with a straight-quotes-only pattern. Curly quotes — what iPad/iPhone keyboards type by default — counted as zero words, so a two-scene run budgeted ~13 words of dialogue and the clip came out far too short for its lines. The pattern now matches both quote styles (apostrophes inside curly quotes, like "don’t", don't break the match).
19Tim Edition identity + plain-language renames (Editor)Teal "Tim Edition 1.0" badge in the header, its own title and favicon, a credit footer, and buttons that say what they do — "Download for Draw Things", "Copy for Draw Things", "Open a Saved Project", tray buttons like "Add Text (Concat)" and "Length from Dialogue 💬". Display only; exports are unchanged. The action bar is sticky, so export is always reachable.
20Renders counter + no-renders guard (Editor)A live "🎬 Renders: N" counter in the action bar uses the Pipeline's own counting rule. At zero, a banner explains the project will report "number of renders: 0" and offers a one-tap Prompt. New Project asks before wiping real work.
21Quick-add templates (Editor)"＋ 🎬 Video Scene" inserts Add Text + Frames by Dialog + Prompt as one block — the correct per-scene structure; "＋ 🖼️ Still Image" inserts a lone Prompt.
22Loop brackets, family colors, collapse, move buttons (Editor)Items inside a Loop are indented under it; unmatched Loops/End Loops are flagged on the item and named in Preview. Every item has a color band by family, ⬆/⬇ move buttons (no dragging needed), and a ▾ collapse toggle.
23Tray search + library drawer + count badges (Editor)A "find an instruction…" box filters the tray by name; the four libraries open as a right-side drawer and their tabs show live entry counts.
24Tray dock: left by default (Editor)The instruction tray now docks as a permanent full-height column on the left instead of the bottom bar; ◀ Left / ▼ Bottom buttons in the tray header switch it, and the choice is remembered.
25Load Image quick-add + image picker (Editor)Quick Add gains "📥 Load Image" (an existing-picture item) alongside Still Image (a Prompt, which is how Draw Things creates a still). Load Image, Load Mask, and Add to Moodboard items get a "🖼️ Pick…" button: pick from Photos or Files and the item fills in the file's name and shows a thumbnail. The image still has to be a PNG in Draw Things' Pictures folder under that name when the Pipeline runs — on iPad, import the photo in Draw Things and Save it with a name first; Photos-app pictures have no file path of their own.
26Missing Pictures file fails in plain words (Pipeline + Editor)A name picked from Photos (e.g. IMG_2129.png) isn't a file in Draw Things' Pictures folder, and the run used to die with a native "Cannot access file" exception and stack trace. Load Image, Load Mask, and Add to Moodboard now stop with a plain-words error naming the file and the fix (import it in Draw Things, Save Full Image under the same name). Using Pick… in the Editor also reveals that warning on the item immediately, before export.
27Picked photos bake into the project (Editor + Pipeline)The real fix for the picker: on Load Image and Add to Moodboard, Pick… now embeds the photo itself in the project (downscaled to ≤1280px, JPEG), and the Pipeline loads it directly — Draw Things accepts image data as a source, which its own Color Fill already relies on. No Pictures file, no Save Full Image bridge. The photo survives project save/load and undo; typing a file name by hand switches the item back to file mode. Preflight and Preview label it "embedded image" instead of dumping the data. Load Mask stays file-based (masks are made inside Draw Things).
28Preflight accepts baked-in photos (Pipeline)The first live run of fix 27 was stopped by Preflight itself: the validator treated the baked-in photo as a file path and demanded a .png/.jpg/.webp extension. It now accepts image data on Load Image / Add to Moodboard, and warning messages no longer quote huge values into the report.
29Header links readable on light backgrounds (Editor)The top links (Documentation, Pipeline, Storyflow Online…) were light sky-blue at a thin weight on the day theme's taupe background — 1.5:1 contrast, nearly invisible. In the day theme they're now dark teal (7:1) and semibold, with an underline on hover; dark themes keep their colors.
30Wildcard names can have spaces (Editor)A Wildcards-tab entry named "tall blonde" silently never resolved — the resolver only matched $ + letters/digits/underscore. Names are now matched against the library itself (spaces fine, $ optional in the name field, longest name wins when names overlap), in both export and Preview. The Wildcard instruction's help line now also says plainly that it runs its own card list and doesn't read the tab.
31Wildcard node fills from the tab (Editor)At Tim's direction ("it should auto populate from the wildcards tab"), the Wildcard instruction gained a "📚 Fill cards from Wildcards tab" dropdown under its cards: pick a tab entry and its options are copied in as the node's cards. The two systems stay separate underneath (tab = picked at export in text; node = picked at runtime in Draw Things) — this is a one-tap bridge, and the fill is a snapshot so saved projects stay self-contained.

Known issues — not yet fixed

  • File-mask layer clearing. Even after fix 7, no instruction can clear the copy of a file-loaded mask already sitting in Draw Things' own mask layer — that still has to be cleared in Draw Things itself. (No API the script uses can reach it; inventing one untested would be worse.)
  • Preview vs export. Preview now expands @ triggers, # shortcuts and $ wildcards (first option) and totals frames correctly — but runtime Wildcard/Sweep items still show only their first card, since their real pick happens during the run.
  • Naming collisions (unchanged from the original): # means config shortcuts in Config items and pose shortcuts in Pose items, and "wildcard" names both the export-time $ system and the runtime Wildcard instruction.

Validation approach

Fixes are checked before they ship here: both files pass a JavaScript syntax check, a diff against the original 261101 files confirms only the intended changes were made, and logic that can run outside Draw Things (like the frames math) is exercised with a small harness over every input position. What can't be checked off-device is an actual run inside Draw Things — if a fix misbehaves there, the original files remain available from wetcircuit's site and in the repo history.
